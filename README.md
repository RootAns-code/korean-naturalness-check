# korean-naturalness-check

한국어 텍스트의 자연스러움을 정량 평가하는 Claude 스킬입니다. 번역투, 매거진투, AI투, 직역체 같은 어색한 표현을 형태소 분석과 코퍼스 통계로 검출합니다.

## 왜 필요한가

LLM은 자기가 쓴 한국어를 자기가 검수하면 자연스럽다고 판정하는 편향이 있습니다. 이 스킬은 LLM 자체 검수와 다른 분포의 **외부 통계 시그널**을 제공해, 자체 검수가 놓치는 어색함을 잡습니다.

## 동작 방식

`scripts/check_naturalness.py`가 문장별로 5개 시그널을 합산해 0~100 점수를 매기고, 임계(17점) 이상을 의심 문장으로 보고합니다.

| 시그널 | 내용 |
|---|---|
| 1. 명사 밀도 | 명사 나열 위주의 번역투 문장 검출 |
| 2. 명사/동사 비율 | 동사가 빈약한 경직 문체 검출 |
| 3. 의존명사+조사 연쇄 | "~것으로의" 류 직역체 검출 |
| 4. 어색 어휘 사전 | 현상 그룹 단위 정규식 사전(`AWKWARD_PATTERN_GROUPS`) 매칭, 확실(18)/강(12)/약(6) 3단계 가중 |
| 5. 코퍼스 결합 빈도 | 동봉 DB에서 3종 결합 룩업 — nv(명사→용언, 하다류 포함), vn(형용사 관형형→명사, "두꺼운 신뢰"), av('-히'계 부사→용언, "급격히 진행") |

시그널 5의 참조 데이터(`assets/kor_collocation.db`, 약 36.5MB)는 Leipzig kor_news_2022_1M 코퍼스의 원문 100만 문장을 kiwipiepy로 형태소 분석해 빌드한 관계별 결합 빈도 SQLite DB입니다(319,683 결합). 런타임 검사기와 같은 추출기로 집계해 DB-런타임 분포가 일치합니다. 빌드 절차는 `scripts/build_collocation_data.py` 참고 — 사용자는 실행할 필요 없습니다.

코퍼스에 없는 명사(2022 이후 신조어 등)는 판정 불가로 침묵하는 대신 `oov_nouns` 필드로 노출되어, 소비자(LLM/파이프라인)가 웹 검색 등 외부 검증으로 이어갈 수 있습니다.

## 사용

Claude Code 또는 Claude.ai에서 한국어 본문을 주고 다음과 같이 요청하면 스킬이 트리거됩니다.

> 이 글 번역투 점검해줘 / 자연스러움 검수해줘 / 이 본문 평가해줘

직접 실행할 수도 있습니다.

```bash
python3 scripts/check_naturalness.py <마크다운 파일> --json
```

## 개발

아래는 이 스킬을 **고칠 때** 필요한 내용입니다. 검수를 실행할 때는 참조하지 않습니다.

## 도구의 검증 정확도와 한계

`eval/run_eval.py` 라벨셋(자연 78문장·어색 80문장, 2.4.0 기준 — 수식 관계 표적 문장 포함) 실측:

- 어색 문장 재현율 85.0% (68/80), 임계 12 재판단 밴드까지 포함 시 90.0%
- 자연 문장 거짓양성률 12.8% (10/78)
- 정밀도 87.2%
- 자연 평균 8.0점 vs 어색 평균 30.5점 (격차 +22.5)

해석 시 유의점 두 가지입니다.

**의심 보고가 항상 옳은 것은 아닙니다.** 남은 거짓양성은 대부분 뉴스 코퍼스에 일상 결합이 없어 생기는 s5 적발(예: 냉장고+남다, 텃밭+심다)입니다. 그래서 s5 단독 근거(어휘 패턴 매칭 없이 `corpus_collocation`만으로 임계를 넘은 문장)는 위의 "0건의 해석" 절차대로 명사 의미를 확인한 뒤 보고합니다. 반대로 `matched`에 확실 신호(이중수동, "~에 있어서" 등)가 잡힌 문장은 실제로 어색할 확률이 매우 높습니다.

**OK 판정도 완전하지 않습니다.** 재현율 86%가 의미하듯 12점 경계선의 어색 문형(단일 수동 한자어, 명사화 '의' 단독 등)은 통과할 수 있습니다. 사용자에게 OK 결과를 보고할 때 이 한계를 함께 안내합니다.

시그널·가중치·임계값·사전을 수정할 때는 반드시 `python3 eval/run_eval.py`로 전후 수치를 비교합니다. 라벨셋은 초기 부트스트랩 세트이므로, 실사용에서 발견되는 거짓양성/거짓음성 문장을 라벨셋에 추가할수록 측정이 정확해집니다.

## 어색 패턴 사전 누적

시그널 5(코퍼스 룩업) 덕분에 정규식 사전에 등록되지 않은 어색 결합도 자동 검출됩니다. 다만 코퍼스가 못 잡는 표현(매거진 명사구, 보고서투 명사화 등 결합 단위가 아닌 패턴)은 여전히 정규식 사전에 누적합니다.

사전은 `scripts/check_naturalness.py`의 `AWKWARD_PATTERN_GROUPS`에 현상 단위 그룹으로 관리합니다. 같은 현상을 겨누는 패턴들이 한 그룹이고, 한 문장에서 그룹당 1회만 가산합니다("것으로 평가되고" 하나가 패턴 3개에 겹쳐 3배 과금되는 것을 막기 위함). 그룹 가중치는 두 단계입니다.

- **12점(강한 신호)**: 자연 한국어에서 거의 안 나오는 문형. 예: 이중수동("되어집니다"), "~에 있어서".
- **6점(약한 신호)**: 자연 용례도 흔한 문체 경향. 예: "의 경우", "것이다", "에 따라". 단독으로는 임계(17)를 못 넘고 다른 신호와 합쳐질 때만 의심으로 분류되게 하여 자연 문장 거짓양성을 막습니다.

새로운 어색 표현을 발견하면 해당하는 그룹에 정규식을 추가하거나, 새 현상이면 새 그룹을 만듭니다. 활용 어미는 `[가나다]` 형태로 묶어 흡수하되, **융합 음절을 빠뜨리지 않도록** 실제 활용형을 나열해보고 문자클래스를 정합니다.

<example>

**좋은 패턴 추가 예시**

```python
r"판단되어[지진질집짐졌]"
```

이 한 줄로 다음 활용형을 모두 잡습니다.

- 판단되어진다 / 판단되어졌다 / 판단되어지고
- 판단되어**집**니다, 판단되어**질**, 판단되어**짐** (융합 음절)

**나쁜 패턴 추가 예시**

```python
r"판단되어[지진졌]"
```

문자클래스에 융합 음절(집/질/짐)이 빠지면 "판단되어집니다", "판단되어질"을 놓칩니다. 실제로 2.2.0까지 이 형태의 클래스 때문에 이중수동 상당수가 통과했습니다(2.3.0에서 수정).

</example>

패턴을 추가·조정한 뒤에는 반드시 `python3 eval/run_eval.py`로 정밀도·재현율 회귀 여부를 실측합니다.

## 동봉 코퍼스 데이터 관리

`assets/kor_collocation.db`는 Leipzig kor_news_2022_1M 패키지(CC BY 4.0)의 **원문 100만 문장**을 kiwipiepy로 형태소 분석해 빌드한 결합 빈도 SQLite DB입니다(총 319,683결합 = nv 286,562 / vn 28,590 / av 4,531, 약 36.5MB). 스킬에 동봉되어 모든 사용자(Claude.ai 웹, PC Claude Code 양쪽)가 별도 셋업 없이 즉시 활용 가능합니다.

빌드 파이프라인의 핵심 원칙은 **DB와 런타임이 같은 추출기를 쓴다**는 것입니다. `build_collocation_data.py`는 `check_naturalness.py`의 `_extract_noun_verb_pairs`를 그대로 임포트해 코퍼스를 집계하므로, 런타임이 조회하는 페어 분포와 DB의 페어 분포가 정의상 일치합니다(2.x 시절 인접 어절 공기표 기반 DB가 "사진을 예쁘게 찍다" 같은 비인접 자연 결합을 0건 거짓양성으로 만들던 구조적 불일치를 차단). 따라서 **추출기 규칙을 수정하면 반드시 DB를 재빌드합니다.** 유의도는 Dunning 로그우도(LLR)를 자체 계산하며, DB의 `build_info` 테이블에 빌드 출처·kiwipiepy 버전이 기록됩니다.

코퍼스를 교체하려면 `scripts/build_collocation_data.py`의 `URL` 상수를 바꾼 뒤 스킬 개발자 환경에서 1회 재빌드합니다(1M 문장 기준 약 2분). 현재 1M이 Leipzig 한국어 뉴스 코퍼스의 최대 규모이며, 2022년판이 최신입니다(2023년 이후판 미제공, 2026-06 확인). 남은 확장 방향은 뉴스 외 도메인(블로그·구어) 코퍼스 추가입니다 — 남은 거짓양성 대부분이 뉴스에 안 나오는 일상 결합이기 때문입니다. 후보 선정 시 웹 크롤 텍스트는 기계번역체 오염 위험이 있어 편집된 한국어(국립국어원 모두의 말뭉치 등)를 우선합니다. 복수 코퍼스를 쓸 때는 "모든 코퍼스에서 0건"일 때만 적발하는 교집합 방식이 거짓양성을 줄입니다.

빌드 스크립트는 사용자가 실행할 필요가 없습니다. 스킬 패키지가 이미 빌드된 DB를 가지고 있기 때문입니다. 빌드 스크립트는 향후 코퍼스 갱신·확장을 위해 스킬 패키지에 포함되어 있습니다.

라이선스 표기: Leipzig Corpora Collection — kor_news_2022_1M, CC BY 4.0, https://wortschatz.uni-leipzig.de/en/download/Korean

## 다른 글 작성 스킬과의 관계

이 스킬은 글 작성 스킬과 직교적입니다. 글 작성 스킬이 본문을 만들고 산출물을 저장한 직후, 사용자가 이 스킬을 호출해 평가받는 흐름입니다.

평가 후 사용자가 결과를 보고 글 작성 스킬에 "이 부분 다시 다듬어줘"라고 지시하는 흐름입니다. 이 스킬에서 본문 자동 수정은 하지 않습니다. 평가와 수정을 분리하는 이유는 평가 도구의 객관성을 유지하기 위해서입니다. 평가하는 LLM이 수정도 하면 자기가 다듬은 표현에 대해 다시 자기가 평가하는 자체 검수 편향이 발생합니다.

### 왜 `tail_sentences`가 따로 필요한가

문단 마지막 문장은 쌍에서 항상 `follow` 자리에만 놓여 **`lead`로 한 번도 판정받지 않습니다.** 문단당 한 문장씩 구조적으로 빠집니다. 실측에서 이 자리에 분열문이 있었습니다.

> 문단26: 낙관 쪽 근거는 반도체에 있습니다. / 트루이스트의 윌리엄 스타인은 ... 봤습니다. / **AI 인프라 주문이 예전보다 규모도 크고 기간도 길어졌다는 게 이유입니다.**

n문장 문단은 쌍이 n-1개라 `lead`가 1~n-1번째를 덮고 `tail`이 n번째를 덮습니다. **둘을 합치면 전 문장이 정확히 한 번씩 검사됩니다**(실측으로 검증: 53문장 = 쌍 31 + tail 22). 1문장 문단도 `solo: true`로 여기 들어옵니다 — 쌍이 없어 통째로 빠지던 자리입니다.

SNS 글처럼 문단이 전부 1문장이면 쌍은 0개지만 tail은 문장 수만큼 나옵니다. 관계 검사는 침묵하고 **구문 검사만 작동**합니다.
### 왜 코드가 판정하지 않는가

판정 기준이 **"그 문장이 정보를 담는가, 뒤 문장을 예고만 하는가"**라는 의미 관계여서 표층 특징으로 근사되지 않습니다. 세 번 시도해서 세 번 실패했습니다.

| 시도 | 실패 |
|---|---|
| 명사서술 종결(`~입니다`) | 같은 병의 64%를 놓침(18편에서 25건 vs 44건). "결과는 러셀 2000에 나타났습니다"처럼 동사로 끝나는 선언이 전부 샘 |
| 구조 정규식(분열문·추상명사 주어) | 관형형 어미가 ㄴ 받침으로 융합되면(되돌**린**, 무너**진**) 문자 매칭 불가. 오탐도 끼어듦 |
| 길이 임계 25자 | 26자 이상을 놓침("금리가 오른 이유는 연준을 못 믿기 때문입니다" 26자, "매출만큼 크게 먹힌 건 ~라는 점입니다" 58자) |

그래서 코드는 **판정 단위만 만듭니다.** 쌍을 명시적으로 열거하는 이유는 "문단을 읽어라"라는 지시만으로는 모델이 눈에 띄는 몇 개만 집고 넘어가기 때문입니다. 쌍을 순회하면 전수가 보장됩니다.

**첫 문장에 한정하지 않습니다.** 문단 중간에도 같은 관계가 있습니다.

> 낙관 쪽 근거는 반도체에 있습니다. / 트루이스트의 윌리엄 스타인은 반도체 투매가 오히려 매수 기회라고 봤습니다. / **AI 인프라 주문이 예전보다 규모도 크고 기간도 길어졌다는 게 이유입니다.**

3번째 문장이 같은 구조인데 첫 문장만 보면 놓칩니다.

- `assets/kor_collocation.db`: [Leipzig Corpora Collection](https://wortschatz.uni-leipzig.de/en/download/Korean)의 kor_news_2022_1M 코퍼스([CC BY 4.0](https://creativecommons.org/licenses/by/4.0/))에서 파생. 원문 100만 문장을 kiwipiepy로 형태소 분석해 관계별 결합 빈도 통계로 집계·변형함. 이 DB 파일 자체도 CC BY 4.0 조건으로 재배포됨.
- 인용: Goldhahn, D., Eckart, T., Quasthoff, U. (2012). *Building Large Monolingual Dictionaries at the Leipzig Corpora Collection: From 100 to 200 Languages.* Proceedings of LREC 2012.
- 런타임 의존성 [kiwipiepy](https://github.com/bab2min/kiwipiepy)(LGPL v3)는 이 저장소에 포함되지 않으며 사용자가 별도 설치합니다.
